# Production Priority & Scheduling Engine (PPSE)

A decision-support system for a contract manufacturer (industrial 3D printing and CNC machining,
~800 customers, thousands of open order lines) that answers, every morning:

1. **What should we produce next?** — a ranked priority queue of every open order line.
2. **Why?** — an explanation generated by the same code that computed the score
   (`+25 Due in 18 hours · +20 Strategic customer · +15 SLA risk · −5 Large setup …`).
3. **What happens if I change it?** — what-if simulation of machine failures, urgent orders,
   extra capacity, material delays, weight changes and more, without touching the real plan.

It connects to an existing ERP/MES **read-only**, normalises the data, scores and schedules the
work, shows a manufacturing control tower, lets managers override and lock the plan with a full
audit trail, and can later write approved schedules back to the ERP through a controlled ladder
(read-only → approval → writeback → controlled auto-scheduling).

> Status: the repository this project started from was empty, so no real ERP was available. The
> system runs end to end against a **mock ERP connector fed by a realistic synthetic plant**; the
> connector abstraction and the field-by-field gap analysis in `docs/ERP_INTEGRATION.md` are the
> starting point for the real integration. See `docs/AUDIT_REPORT.md` for the full audit.

## Architecture at a glance

```
ERP / MES  ──(read-only connector)──►  Integration layer  ──►  Normalised manufacturing model
                                        (normalise, validate,      (PlanningSnapshot: customers,
                                         reconcile, sync runs)      orders, operations, machines,
                                                                    materials, tooling, calendars,
                                                                    locks, overrides, expedites)
                                                                             │
                 ┌───────────────────────────────────────────────────────────┤
                 ▼                       ▼                    ▼              ▼
          Data-quality engine     Priority engine      Constraint engine   Calendar engine
          (blocking / warning     (weighted factors,   (hard + soft,       (shifts, holidays,
           issues, dashboard)      adjustments,         readiness)          downtime)
                                   explanations)             │
                                         └──────────┬────────┘
                                                    ▼
                                      Scheduling engine (rule-based V1,
                                      CP-SAT re-sequencer, quality score)
                                                    │
              ┌───────────────┬─────────────────────┼────────────────┬──────────────┐
              ▼               ▼                     ▼                ▼              ▼
        Analytics        Simulation           Replanning         Alerts        Writeback
     (KPIs, capacity,    (scenarios,         (triggers,                        gateway
      bottlenecks, OTD)   diff)               stability)                       (read-only first)
                                                    │
                        Application services · REST API · background worker · audit trail
                                                    │
                                  React control-tower UI (16 screens)
```

* **Backend**: Python 3.11, FastAPI, SQLAlchemy 2 + Alembic, Pydantic 2, structlog, APScheduler,
  optional OR-Tools. PostgreSQL 16 in dev/prod, SQLite in unit tests.
* **Frontend**: React 18 + TypeScript + Vite, TanStack Query, Recharts, custom SVG Gantt.
* **Engines are pure**: they only see the in-memory `PlanningSnapshot`, are deterministic for a
  given snapshot + configuration, and never touch the database or the ERP.
* **Everything is configurable and versioned**: priority weights and thresholds, customer rules,
  SLA, aging/fairness, expedite rules, locking, stability, batching, objectives, alert thresholds,
  data-quality severities — stored as versioned configuration with diffs and rollback.
* **Everything is auditable**: input snapshot, algorithm and configuration versions, optimisation
  run metrics, schedule versions (draft → approved → published → superseded) and every human
  override with user, timestamp, previous/new value and reason.

## Quick start (Docker)

```bash
cp .env.example .env            # adjust secrets; defaults run a self-contained demo
docker compose up --build       # db → migrate → seed + sync (synthetic plant) → backend, worker, frontend
```

* UI: <http://localhost:8080> (login `admin` / `admin123`; one seeded user per role, see
  `backend/app/db/seed.py`)
* API: <http://localhost:8000/api/v1> · OpenAPI docs at <http://localhost:8000/docs>
* First plan: log in as a planner or manager and press **Generate schedule** (or
  `POST /api/v1/schedule/generate`).

## Local development

```bash
# backend
cd backend
python3.11 -m venv .venv && .venv/bin/pip install -e ".[dev,optimization]"
export PPSE_DATABASE_URL=postgresql+psycopg://postgres:postgres@127.0.0.1:5432/ppse
.venv/bin/python -m app.cli migrate
.venv/bin/python -m app.cli seed
.venv/bin/python -m app.cli sync --mode full --scale medium   # mock ERP → local store
.venv/bin/uvicorn app.main:create_app --factory --reload --port 8000
.venv/bin/python -m app.cli worker                            # optional: sync / replan / alert jobs

# frontend
cd frontend
npm ci && npm run dev                                          # http://localhost:5173, proxies /api → :8000
```

Checks: `ruff format --check app tests synthetic && ruff check app tests synthetic && mypy app` and
`pytest -q` in `backend/`; `npm run typecheck && npm run lint && npm test -- --run && npm run build`
in `frontend/`. Set `PPSE_TEST_DATABASE_URL` to also run the PostgreSQL variants of the
integration tests. Details in `docs/TESTING.md`.

## Roles

`admin` (configure everything) · `production_manager` (override priorities, lock, approve/publish)
· `planner` (adjust schedules, run simulations, hold/release) · `supervisor` (view, acknowledge
alerts) · `operator` (view assigned jobs) · `executive` (read-only dashboards).

## Roadmap

Delivered: read-only integration layer with mock ERP, normalised model, priority engine V1,
rule-based scheduler V1 with CP-SAT re-sequencing groundwork, what-if simulation, control-tower UI,
overrides/locks/expedites, continuous replanning with stability rules, alerts, data-quality
dashboard, full audit trail, versioned configuration, Docker/CI. Next: the real ERP connector
(discovery checklist in `docs/ERP_INTEGRATION.md`), approval-mode writeback, richer multi-objective
optimisation, and the AI layer on top of the deterministic core (forecasting, natural-language
queries) described in `docs/REQUIREMENTS.md`.
